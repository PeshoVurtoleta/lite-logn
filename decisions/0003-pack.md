# 0003 -- Pack discipline / files[] (D-07)

- Status: ACCEPTED
- Severity: S3 (scaffolding / hygiene, enforced every release)
- Date: 2026-09-17
- Session: S0 (scaffold)

## Context

The published tarball must ship the runtime + docs and NOTHING else. Dev infra
-- the test suites, the witness / torture harnesses, the benchmark suite, the
ADRs, any future demo -- is repo-only: valuable as source and as published
RESULTS (tables / graphs in README + GUIDE), but never shipped. This mirrors
lite-o1's shape exactly.

## Decision

`files[]` ships EXACTLY these six files:

```json
["LogN.js", "LogN.d.ts", "llms.txt", "README.md", "CHANGELOG.md", "LICENSE"]
```

These are repo-only and MUST NOT appear in `npm pack --dry-run`:

- `test/` (all suites + `torture.mjs` + `witness.mjs` + `perf/` + `types/`)
- `benchmark/` (the ADOPTED lite-o1 Bench v2 suite)
- `decisions/` (these ADRs)
- `demo/` (a later session's repo-only artifact)
- `RESEARCH.md`, `ROADMAP.md`, `GUIDE.md`

`.gitignore` additionally excludes `benchmark/results.json` and
`benchmark/report.html` (machine / time-specific generated artifacts).

## Enforcement

- `test/QaAudit.test.js` asserts, from `package.json`, that `files[]` is exactly
  the six-entry list above and contains none of the repo-only paths.
- Every `/release` runs `npm pack --dry-run` and the pack check asserts a
  six-file tarball; a seventh file is a release-blocking failure.

## Consequences

- The witness harness and the benchmark suite never bump their own version;
  `LogN.js` stays byte-identical when they change. Their published value is the
  RESULTS embedded in the docs, not the code.
- A new repo-only directory (e.g. `demo/`) needs no `files[]` change -- it is
  excluded by default.

## Alternatives rejected

- **Ship `GUIDE.md` in the tarball.** Rejected: it is a repo-only decision guide
  (like lite-o1's); the README is the shipped doc. Keeping GUIDE repo-only keeps
  the tarball to six files.
